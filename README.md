## 它是怎么算的

### ① 选的是套餐里的每一轮，不只是整份套餐

麦当劳 MCP 的 `query-meal-detail` 会返回套餐每一轮的官方候选和差价，本项目按轮次解算。
`人气经典随心配`（¥14.9）的蓝区（主食）有 8 个官方候选：

| 候选 | 差价 | 辣味 | 含鸡 |
|---|---:|:--:|:--:|
| 双层吉士汉堡（默认） | +¥0 | 否 | 否 |
| 高达吉士双牛堡 | **−¥1** | 否 | 否 |
| 麦香鱼 | +¥0 | 否 | 否 |
| 那么大鸡排（椒盐风味） | **−¥1** | 否 | 是 |
| 酥酥多笋卷 | **−¥1** | 是 | 否 |
| 麦乐鸡5块 | **−¥1** | 否 | **是** |
| 麦香鸡 | **−¥1** | 否 | **是** |
| 小薯条 | **−¥1** | 否 | 否 |

于是不吃辣的人从双牛堡 / 麦香鱼 / 椒盐鸡排里挑，想吃鸡的从麦香鸡 / 麦乐鸡里挑——
**每人从官方给出的合法选项里选**，而不是靠菜名关键词去猜套餐里到底有什么。

### ② 约束无解就整份弃用，不硬凑

`全明星双人分享餐`（¥49.9）的"选择汉堡"轮只有 `麦辣鸡腿汉堡` 和 `酥酥多笋卷`——
**两个都辣**。对不吃辣的人这份餐**整个不可用**，引擎直接放弃并退到 `麦麦周末双人餐`，
而不是端上去再解释一句"可能有点辣"。

判定依据是数据不是猜测：任一**必选轮次**找不到合法候选，整份餐品就出局。

### ③ 读懂 `diffPrice`，套餐比单点省 15.5 元

`巨无霸三件套`（¥37.5）的小食轮里，`小杯玉米杯` 的差价是 **−¥1**，比默认中薯条还便宜。

- 巨无霸单品 ¥26.5 + 脆脆薯条 ¥16 + 可乐 ¥9.5 = **¥52.0**
- 巨无霸三件套（配小杯玉米杯）= **¥36.5** → **省 15.5 元**

只看餐品价格，算不出这一层。

## 跟着当季活动走

麦当劳的活动话术会渗进菜单名：活动叫「就「酱」心有所「薯」」，菜单就多个「鸡薯双全盒」；活动叫「“韩”风刮到了四件套」，菜单就多一整个「龙焰鸡腿堡」系列。

所以会拉 `campaign-calendar` 对上号。2026-10-10 识别出龙焰鸡腿堡三件套、龙焰芝士棒鸡腿堡、蓝莓爆爆珠麦旋风、灰焰圆筒、鸡薯双全盒等 7 项，还能抽出营销话术和谐音梗落点（`就「酱」心有所「薯」` → `['酱','薯']`）。

**设计成活动无关**——不写死世界杯或春节，换任何联名节庆都自动生效。

## 🥗 减脂也能吃：热量是真的算出来的

减肥点麦当劳是最难的。这里按 `list-nutrition-foods` 的 160 条营养数据核算，
**套餐热量按轮次组件逐个累加**——`巨无霸三件套[巨无霸 + 小杯玉米杯 + 可乐中杯]`
= 513 + 53 + 147 = **713 kcal**，三个数都在表里，不是估的。

| 品项 | kcal | | 品项 | kcal |
|---|---:|---|---|---:|
| 芝士双层安格斯厚牛堡 | 1003 | | 可乐中杯 | 147 |
| 培根双层安格斯厚牛堡 | 987 | | **无糖可口可乐** | **0** |
| 培根安格斯厚牛堡 | 707 | | 小杯玉米杯 | 53 |
| 巨无霸 | 513 | | 圆筒冰淇淋 | 93 |
| 板烧鸡腿堡 | 391 | | 锡兰红茶 | 2 |

给个 `calorieTarget`（比如 800），`light` 策略就会按热量升序排，超标自动提醒：

```
🥗 轻食低卡  ·  热量升序，配热量目标用

   合计 ¥114.30      人均 ¥28.57
   热量 1427 kcal      人均 357 kcal

  P1  麦香鱼              ¥22.00  325kcal
  P2  麦香鸡              ¥16.50  369kcal
  P3  板烧鸡腿堡          ¥23.50  391kcal
  P4  酥酥多笋卷          ¥20.50  342kcal
```

**减脂的还能更便宜**——这一单 ¥114.30，比性价比首选的 ¥138.40 还低。

### 会给替换建议，但不给编造的数

```
💡 把「可乐中杯」换成「无糖可口可乐中杯」，省 147 kcal
```

这个换有据可依——两个都在营养表里，147 是减出来的。

### 去酱建议只给名字，不给数字

`query-meal-detail` 的 `modification` 会告诉你哪些酱料可以去掉（巨无霸酱、吉士…），
所以能建议 **"可以去掉巨无霸酱"**。

但**接口没提供去掉后的热量**，所以**不会说"省 200 大卡"**——那句话只能是编的。

### 三条诚实边界

- ⚠️ 营养表**只有单品没有套餐**，套餐必须按轮次组件累加；任何一环查不到就整体标"未知"，**绝不用同类估算**
- ⚠️ **"去酱省多少大卡"查不到**，只给名称
- ⚠️ 热量是**参考值**，不构成营养或医疗建议

## 📍 先选门店，别急着点餐

没有门店就没有菜单、没有价格、没有券。`query-nearby-stores` 会把附近的店全列出来，
但不该让你在一堆店里面自己挑——`stores.py` 会：

- **滤掉此刻已打烊的**（跨零点营业的店也判对：23:50 还能选到 01:00 / 02:00 关门的那几家）
- 按距离排序，标出**是否支持预约**、今天还剩哪些时段
- 给一句话推荐

```
📍 门店

  推荐  麦当劳衡阳船山餐厅（3390023）
        864 米 · 支持预约，今天还有 午餐(10:44至14:15)，下午茶… · 营业到 23:59

  ★ 麦当劳衡阳船山餐厅  864 米  蒸湘北路30号步步高超市一楼
    麦当劳衡阳大洋百货餐厅  887 米  解放路121号大洋百货
```

凌晨三点查附近麦当劳，不会给你推一排已经关门的店。

## 分账：零尾差

浮点数在钱上不靠谱，`13.9 / 3 = 4.6333...`，四舍五入后经常差几分。
这里**全程整数分**运算，余数按序分配：10 元分 3 人 = `334/333/333`。

```
A  应付 ¥24.15
    ¥13.90  人气经典随心配
    ¥15.90  鸡薯双全盒 ×2（共享）
    -¥5.70  整单优惠均摊
合计   ¥96.60   人均 ¥24.15
校验   ✅ 零尾差，合计与实付分毫不差
```

## 装

### 一句话：绑定**你自己的**麦当劳账号

MCP 接入、选配解算、预算裁剪、核价、分账、热量核算——这些项目都替你做完了。
你只需要做一件事：**让麦当劳 MCP 认你**。

为什么这一步必须你来：`mcp.mcd.cn` 是**账号级**接口，优惠券、积分、订单都挂在
**你自己的麦当劳账号**上。所以用的不是我的 token，是**你的**——
换来的是**你的券、你的积分**。这也意味着：**别人跑这个项目，看到的是他自己的券，不是我的。**

### ① 拿 Token

[open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 手机号登录 → 右上角【控制台】→【激活】→ 复制

### ② 配连接器

**不绑定任何客户端。** 本项目是一份 MCP Skill + 一套纯 Python 引擎，
你手上是什么 MCP 客户端就用哪份 JSON。下面以几个常见的为例：

<details>

<details>

【设置】→【MCP】→【添加】→ 下拉选【从 JSON 导入】→ 粘贴下面这段

<details>
<summary><b>Trae / VS Code / Kiro / 任何支持 Streamable HTTP 的客户端</b></summary>

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamableHttp",
      "url": "https://mcp.mcd.cn",
      "headers": { "Authorization": "Bearer YOUR_MCP_TOKEN" }
    }
  }
}
```

> 嫌麻烦就直接让 Agent 帮你写，它会照着 `mcp-config.example.json` 填好。
> 改完配置**要重启客户端**才生效。
> 🔒 Token 只放本地。本仓库的 `mcp-config.example.json` 只有 `${MCD_MCP_TOKEN}` 占位符。

**客户端要求**：必须支持 **Streamable HTTP**。各家接法见
[麦当劳官方文档](https://github.com/M-China/mcd-mcp-server)。

### ③ 用起来

把 `SKILL.md` 和 `scripts/` 交给你的 Agent。
依赖：**Python 3.9+，仅标准库**，无需 pip install。

命令行也能跑（**全离线，不联网、不要 Token**）：


## 边界（先看这段）

- ⚠️ **辣味是名称与标签的关键词判定**，麦当劳没有成分表或过敏原字段。**不构成过敏建议。**
- ⚠️ 没拉过详情的套餐标「**辣度未确认**」，而不是默认不辣。点单时自己看一眼。
- ⚠️ **热量是参考值**，营养表只有单品没有套餐；"去酱能省多少大卡"接口没给，不编。
- ⚠️ **不下单**。只到核价为止。
- ⚠️ 价格与供应以麦当劳官方渠道实时结果为准。

### 关于「每个人看到的不一样」

菜单、价格、营养这些是**全国统一**的，任何人查都一样。

但**优惠券是账号级的**——`mcp.mcd.cn` 认的是你的麦当劳账号，所以：

- 你看到的是**你卡包里的券**，别人看不到你的，你也看不到别人的
- 券按日期生效，今天有没有券取决于**你什么时候问**
- 门店营业时间、菜单是**实时**的，不同城市不同时间查到的结果本来就不同

这不是限制，是接口的设计。换个人跑这个项目，**菜单、价格、热量、门店优选全都一样**，
只有券那一栏会因人而异。

所以实测记录里"某店当天无券"只说明**那天那家店当时的状态**，不是这个项目的限制。

## 安全
