# 麦麦拼餐师 · mcd-meal-mate

> 朋友一起点麦当劳，最烦的不是挑，是**挑完还要算**：谁不吃辣、谁想吃鸡、预算多少、券能不能用、到底谁垫钱。
> 这个 Skill 输入人数和预算，直接给出**四套方案**，每个人都能吃到想吃的，总价由麦当劳官方接口核算过。

## 它解决什么

一群人点单，真正的难点不是"推荐什么"，而是**约束下的分配**：

- 有人不吃辣，但最划算的套餐里正好有辣味轮次
- 有人想吃鸡，可"三件套"的轮次里根本没有鸡肉选项
- 预算 180，但"最划算的单品组合"要 220
- 想用券，结果发现**今天的券全部指定了别的日期**

本项目的做法是：**把这四件事分开处理，再合并成方案**。

## 和多数「拼餐/预算点餐」项目的区别

这个赛道挤了不少同类项目。大多数做到的是**餐品级**——从菜单里挑几个菜名，算个总价。
本项目往下钻了一层，做**轮次级**的选配定制：

| 能力 | 多数项目 | 本项目 |
|---|---|---|
| 选择粒度 | 选整份套餐 | **选套餐里的每一轮**（主食 / 小食 / 饮料各自选） |
| 忌口判定 | 靠餐品名关键词猜 | 读 `query-meal-detail` 的官方 `choices`，**逐轮判定合法性** |
| 套餐内优化 | 无 | 解析 `diffPrice`，**自动挑负差价选项** |
| 约束无解时 | 硬凑，或照常推荐 | **必选轮次全违规则整份弃用并回退** |
| 当季活动 | 无，或人工挑 | `campaign-calendar` **自动识别活动限定品**并参与决策 |
| AA 分账 | 常缺失 | **整数分运算的零尾差分摊**，合计与实付分毫不差 |
| 没验证过的信息 | 默认"不辣" | 标注 `spicyUnknown`，**不下结论** |
| 定价可信度 | 本地估算 | 四套方案**全部经 `calculate-price` 官方核验**，附实测记录 |
| 自动化 | 无 | GitHub Actions：4 组合（双系统 × 双版本）跑 102 项自测 |

### 举三个真实的例子

**① 忌口做到轮次级，才是真的做到**

`人气经典随心配`（¥14.9）的蓝区有 8 个官方候选。不吃辣的人从高达吉士双牛堡 / 麦香鱼 / 椒盐鸡排里挑，想吃鸡的从麦香鸡 / 麦乐鸡里挑——**每个人都从官方给出的合法选项里选**。关键词匹配只能告诉你"这个套餐叫板烧鸡腿堡"，而轮次级能告诉你"这个套餐里的主食还能换成麦香鱼"。

**② 必选轮次无解，整份弃用**

`全明星双人分享餐八件套`（¥49.9）看着很划算，但它的"选择汉堡"轮只有两个候选——`麦辣鸡腿汉堡` 和 `酥酥多笋卷`，**两个都是辣的**。

对明确不吃辣的人，这份餐**整个不可用**。本项目会直接放弃它、退到 `麦麦周末双人餐`，而不是把辣餐端上去再解释一句"可能有点辣"。

**③ 读懂 `diffPrice`，套餐比单点省 15.5 元**

`巨无霸三件套`（¥37.5）的小食轮里，`小杯玉米杯` 的差价是 **`- ¥1`**，比默认的中薯条还便宜。

- 巨无霸单品 ¥26.5 + 脆脆薯条 ¥16 + 可乐 ¥9.5 = **¥52.0**
- 巨无霸三件套（选小杯玉米杯）= **¥36.5** → **省 15.5 元**

引擎会自动找这类差价并选它。所以"极致省钱"策略**优先套餐而不是拿裸单品拼**——这是只看餐品价格永远算不出来的。

## 跟着当季活动走

麦当劳的活动话术会渗进菜单名：活动叫「就「酱」心有所「薯」」，菜单里就多一个「鸡薯双全盒」；活动叫「“韩”风刮到了四件套」，菜单里就多一整个「龙焰鸡腿堡」系列。

所以本项目会拉 `campaign-calendar`，把**当前正在跑的活动**和菜单对上号：

```
$ python scripts/campaign.py data/sample-campaigns.json data/sample-case-4p-180.json plans.json
```

2026-10-10 实测识别结果：

| 状态 | 餐品 | 来自哪条活动 |
|---|---|---|
| today | 龙焰鸡腿堡三件套 | 麦当劳联动 G-DRAGON |
| today | 龙焰芝士棒鸡腿堡 | 麦当劳联动 G-DRAGON |
| today | 蓝莓爆爆珠麦旋风 | 🫐一口爆汁！蓝莓爆爆珠麦旋风上新 |
| today | 灰焰圆筒 | 🩶灰白撞色，灰焰圆筒酷爽登场 |
| today | “我就喜欢”鸡薯双全盒 | 韩式风味蘸酱上新 |

**做了三件事：**

1. **识别** —— 剥掉「“我就喜欢”」这类引号前缀和「三件套」这类通用后缀，拿核心词去活动文案里匹配
2. **提取话术** —— 顺带把营销话术抽出来，包括谐音梗的落点（`就「酱」心有所「薯」` → `['酱','薯']`）
3. **参与决策** —— 「口味优先」策略下活动限定品获得优先级；「极致省钱」和「均衡」**不受影响**，因为它们的价格优先语义不该被活动带偏

**设计成活动无关**：不写死「世界杯」「春节」这类具体活动，换成任何联名、节庆、暑期活动都自动生效，改代码都不用。

⚠️ 这是**文本匹配**，不是官方标注。匹配上只能说「活动文案里提到过它」，不能断言「这就是限定款」，所以输出统一叫「活动关联」。

## 分账：整数分运算，零尾差

点完餐总要分账，而这是最容易出错的地方——浮点数在钱上不可靠，`0.1 + 0.2 != 0.3`，`13.9 / 3 = 4.6333...`，四舍五入之后经常差几分。

本模块**全程用整数分**运算，余数按固定顺序分配：

```
$ python scripts/split_bill.py plans.json cheapest
```

```
P1  应付 ¥24.15
    ¥13.90  人气经典随心配（高达吉士双牛堡 + 可乐麦炫酷）
    ¥15.90  “我就喜欢”鸡薯双全盒 ×2（共享）
    -¥5.70  整单优惠均摊
P2  应付 ¥24.15
    ...
合计   ¥96.60
人均   ¥24.15
校验   ✅ 零尾差，合计与实付分毫不差
```

分摊规则：个人专属餐归本人 → 共享餐全桌均分 → 分享餐只在成员间分 → 整单优惠按人数均摊。**每一步都断言 `sum(每人) == 实付`**，一分不差。

场景：4 人 · 预算 ¥180 · 堂食 · 2 人不吃辣 · 1 人想吃鸡
门店：麦当劳衡阳船山餐厅（`storeCode=3390023`），2026-10-10 实测

| 方案 | 策略 | 预估总价 | 人均 | 说明 |
|---|---|---:|---:|---|

## 三个让它变聪明的设计

### 1. 忌口不靠猜，靠官方候选清单

麦当劳菜单里**没有过敏原字段**，`tags` 里也没有"辣/不辣"。但套餐详情 `query-meal-detail` 会给出**结构化候选**：

`人气经典随心配`（¥14.9）的蓝区（主食）8 选 1：

| 候选 | 差价 | 辣味 | 含鸡 |
|---|---:|:--:|:--:|
| 双层吉士汉堡（默认） | +¥0 | 否 | 否 |
| 高达吉士双牛堡 | **−¥1** | 否 | 否 |
| 麦香鱼 | +¥0 | 否 | 否 |
| 那么大鸡排（椒盐风味） | **−¥1** | 否 | 是 |
| 酥酥多笋卷 | **−¥1** | 是 | 否 |
| 麦乐鸡5块 | **−¥1** | 否 | **是** |
| 麦香鸡 | **−¥1** | 否 | **是** |
| 小薯条 | **−¥1** | 否 | 否 |

于是不吃辣的人从双牛堡/麦香鱼/椒盐鸡排里挑，想吃鸡的从麦香鸡/麦乐鸡里挑——**每个人都从官方给出的合法选项里选，而不是靠关键词去猜套餐里到底有什么**。

### 2. 会算"隐藏的便宜选项"

`巨无霸三件套`（¥37.5）的小食轮里，`小杯玉米杯` 的差价是 **−¥1**，比默认的中薯条还便宜。

- 巨无霸单品 ¥26.5 + 脆脆薯条 ¥16 + 可乐 ¥9.5 = **¥52.0**
- 巨无霸三件套（选小杯玉米杯）= **¥36.5** → **省 15.5 元**

引擎会自动找这类差价并选它。所以"极致省钱"策略**优先套餐而不是拿裸单品拼**。

### 3. 该弃用就弃用，不硬凑

`全明星双人分享餐八件套`（¥49.9）看起来很划算，但它的"选择汉堡"轮只有两个候选——`麦辣鸡腿汉堡` 和 `酥酥多笋卷`，**两个都是辣的**。

对明确不吃辣的人，这份餐**整个不可用**。引擎会直接放弃它、退到下一款（`麦麦周末双人餐`），而不是把辣餐端上去再解释一句"可能有点辣"。

## 安装

### 1. 申请麦当劳 MCP Token

访问 [open.mcd.cn/mcp](https://open.mcd.cn/mcp) → 手机号登录 → 右上角【控制台】→【激活】→ 复制 Token。

### 2. 配置连接器

在 WorkBuddy 左侧【连接器】→ 右上角【自定义连接器】→【配置 MCP】，填入：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamableHttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      }
    }
  }
}
```

> ⚠️ 改完配置**需要重启客户端**才能生效。
> 🔒 **Token 只放本地配置，不要提交到仓库。** 本仓库的 `mcp-config.example.json` 只用 `${MCD_MCP_TOKEN}` 占位符。

其他客户端（Cherry Studio / Cursor / Trae / VS Code / Kiro）的接入方式见 [官方文档](https://github.com/M-China/mcd-mcp-server)。

### 3. 安装本 Skill

把仓库放到你的 skills 目录，或直接把 `SKILL.md` 与 `scripts/` 交给你的 Agent 使用。

**依赖**：Python 3.9+，**仅标准库**，无需 pip install。

## 能力边界（请先读这一段）

这是一个**点单规划器**，不是营养师，也不是过敏原检测器：

- ⚠️ **辣味判定是名称与标签的关键词启发式**，麦当劳 MCP 没有提供成分表或过敏原字段。**本项目不构成过敏建议，不能用于确认食物是否安全。**
- ⚠️ **没拉过详情的套餐会被标注「辣味未确认」**，而不是默认"不辣"。宁可不结论，也不给假结论。
- ⚠️ **券是动态的**。实测该门店 2026-10-10 当天无券（卡包里 13 张全部指定了其他日期，其中 9 张仅限早餐时段）。所以"今天有没有券"每次都要现场查——本项目不写死、不用卡包券冒充可用券。
- ⚠️ **本项目不下单**。只到 `calculate-price` 核价为止。真要下单会把门店、餐品、选配、优惠、金额完整列出来，等你明确确认后再走 `create-order`。
- ⚠️ 价格、库存、供应状态**以麦当劳官方渠道实时结果为准**。本项目为参赛作品，非麦当劳官方产品。

## 四种策略怎么选

| 策略 | 什么时候选 |
|---|---|
| `cheapest` 极致省钱 | 预算很紧，能省则省，一个人吃饱就行 |
| `balanced` 均衡 | 默认推荐；便宜但不寡淡，且每人吃得不一样 |
| `tasty` 口味优先 | 预算宽松，想吃好点、想试试新品 |
| `share` 多人分享 | 5 人以上，双人分享餐按份更划算 |

## 安全与合规

- 仓库内**不含任何真实 Token、密钥、账号凭证**；配置示例只使用 `${MCD_MCP_TOKEN}` 环境变量占位符。
- 所有菜单数据来自 MCP 实时返回，项目不内置、不缓存、不修改餐品信息。
- 仅使用麦当劳 MCP 的只读接口 + `calculate-price` 核价，**不调用** `create-order`、`auto-bind-coupons`、`draw-lottery` 等会改动账户状态的接口。
- 遵守 MCP 限流（每 Token 每分钟 600 次请求）；一次规划通常 3~8 次调用，组合枚举放在本地完成。
